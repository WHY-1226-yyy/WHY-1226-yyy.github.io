【MySQL实战指南】从零到一：我的48小时数据库通关笔记

筑基篇：库表创建与数据类型

环境搭建与客户端（DBeaver）的高效配置

  • 下载MySQL

    • 双击运行，选 Server only 或 Developer Default
    • 设置 root 密码（一定要记住！）
    • 勾选”配置为Windows服务”，开机自启
    • 命令行输入 mysql -uroot -p 验证
    • 输入安装时设置的密码，看到 mysql> 提示符就说明连接成功了
    • 连接后试试show databases
  • 下载DBeaver

    • 下载下来后，双击安装包，一路点击“Next”直到安装完成（如果安装过程有让你选语言，选中文或者英文都可以）
  • 创建连接
    • 打开 DBeaver（图标是一只可爱的松鼠）
    • 第一次打开，可能会弹出一个“创建新连接”的欢迎窗口；如果没有弹，就点击左上角工具栏里一个 带绿色加号的插头图标（或者点击顶部菜单栏 数据库 -> 新建数据库连接）。
    • 在弹出的数据库列表里，找到并点击 MySQL，然后点“下一步”。
    • 下载驱动（关键）：如果你第一次用，它会提示你缺少 MySQL 驱动，点击窗口下方的 “下载(Download)” 按钮，它会自动帮你下载好。
    • 填写连接信息（严格按照下面填）：
    • 点击左下角的 “测试连接 (Test Connection)”
    • 如果弹出一个窗口显示 “已连接 (Connected)”，并带有版本信息，那就说明完美连接上了！ 点击“确定”，再点击“完成”。

探索篇：查询、约束与索引

  • SELECT 查询：SQL 的灵魂所在

  • 列别名 与 DISTINCT 去重

    • 列别名 as 给列起个好懂的别名，结果表头显示中文
      as 可以省略，直接空格写别名
    • DISTINCT 去重 查询结果中重复的行只保留一条
      比如查有哪些部门，不要每个部门重复显示

  • WHERE：只查满足条件的行

    • select 列名 from 表名 where 条件;
    • 示例：查工资大于10000的员工

  • AND / OR / NOT：组合多个条件

    • AND 并且（同时满足） 工资大于8000 并且 年龄小于30
    • OR 或者（满足一个） 技术部 或者 产品部的员工
    • NOT 取反 不是财务部的所有员工

  • LIKE：模糊匹配字符串

  • IN / BETWEEN / IS NULL

    • IN 在多个值里 等于这些值中任意一个就行
      相当于 where dept=’技术’ or dept=’产品’ or dept=’运营’
    • BETWEEN 范围 在某个闭区间内（包含两端）相当于 salary>=8000 and salary<=15000
    • IS NULL 是空值 判断是不是NULL（空值）
      注意：不能用 = null，必须用 is null

  • ORDER BY：按某列排序

    • select 列名 from 表名 order by 列名 asc/desc;
    • 示例：按工资从高到低排序

  • LIMIT：分页查询

    • select 列名 from 表名 limit 偏移量, 行数;
    • 示例：每页10条，查第1页和第2页

  • 聚合函数

  • GROUP BY：按组统计

    • 想知道每个部门的平均工资是多少？

  • HAVING：分组后再过滤

    • 只看平均工资大于10000的部门？

  • 多表查询：把两张表连起来查

    • 员工表有部门ID，部门表有部门ID和部门名，想查员工姓名+部门名

  • INNER JOIN：标准内连接写法

    和前面 where 写法的区别：

    · 效果完全一样，只是写法不同，inner join 更清晰
    · 连接条件写在 on 后面，过滤条件写在 where 后面

  • LEFT JOIN / RIGHT JOIN

    • LEFT JOIN 左外连接 左表（employee）全部保留
      右表匹配不上的列显示NULL
      没部门的员工也会查出来
      只是部门名那一列是NULL
    • RIGHT JOIN 右外连接 右表全部保留
      左表匹配不上的列显示NULL
      没员工的部门也会查出来
      只是员工信息那一列是NULL

  • 子查询：查询套查询

    • 查工资比”张三”高的员工？

  • PRIMARY KEY：主键约束

    • 作用：唯一标识一行数据，不能为空，不能重复
    • 建表时指定主键

  • FOREIGN KEY：外键约束

    • 作用：表和表之间建立关联，保证数据一致性

  • 唯一 / 非空 / 自动增长

    • UNIQUE 唯一约束 列值不能重复，可以有一个NULL
      比如用户名不能重复
    • NOT NULL 非空约束 这一列必须有值，不能是NULL
      比如姓名不能为
    • DEFAULT 默认值
    • AUTO_INCREMENT 自动增长

  • 索引：让查询变快的”目录”

    • 书的目录。不看目录要一页一页翻，看目录直接跳到那页
    • 创建索引 给name列建普通索引
      idx_ 开头是命名惯例
    • 查看和删除索引 查看表上有哪些索引
      删除指定索引
